# Interlude 5.5 — Hardening & Value (pre-PRD-6)

> **Status:** in progress · **Phase:** MVP hardening · **Type:** cross-cutting interlude (not a bounded-context PRD)
> A short pass between the MVP (PRDs 0–5) and Clinical/EHR (PRD-6) to close foundational gaps a business-
> model + architecture review surfaced. Built TDD, one slice per branch/PR, same as the PRDs.

## Why

The MVP works, but a review found: (1) the app is **single-user in practice** — signup creates one admin and
there's **no UI to add staff**, so the people meant to drive the app can't be created, and RBAC is inert;
(2) **money is float math** behind a `decimal:2` cast and **LTV is a read-modify-write** — both wrong for a
billing product; (3) authorization is four coarse Gates with no object-level model, the moment before
clinical data (LGPD) lands; (4) several screens **load entire tables** into dropdowns each render (the
in-house searchable-select was designed but never built); (5) the differentiator — the **recall/recovered-
revenue** story — is computed but **never rendered** (it's stuck behind PRD-9). This interlude fixes the
foundation and makes the value visible before we stack EHR on top.

## Scope

**In:** clinic **staff/user management** + a **capability-based RBAC** (Policies where object-level checks
exist); **exact money math** (BCMath, no new dependency, no schema change) + **atomic** LTV/counters; the
in-house **`x-ui.combobox`** + gating the load-everything dropdowns; **plumbing** (Pest `->in()` glob,
migration-ordering convention, consistent listener registration) + a **domain-event log** seam (the funnel
instrumentation the TS app had and we don't); and a **recall + revenue dashboard** (a thin pull-forward of
PRD-9) so the ROI is demo-able.

**Out:** full finer-role taxonomy (reception/medical/financial) beyond the capability seam — PRD-6 adds the
`medical` capability when clinical data defines it; email-based invites (we create users with a set
password for now); the full PRD-9 analytics suite (charts/exports); billing/subscriptions (PRD-13).

## Build slices (tracer bullets, TDD)

1. **Team management + RBAC** — an admin **Equipe** settings page to list/create/edit-role/activate-
   deactivate clinic users (name, email, role admin/staff, set password); a `Capability` map on
   `UserRole` as the single source of truth (Admin: all; Staff: patients/pipeline/scheduling/financial,
   **not** clinic settings or users); the existing Gates redefined **from** that map + a new
   `manage-users` (admin-only); a `UserPolicy` guarding team management with **last-admin protection**
   (can't deactivate/demote the only admin, can't self-lock-out). A created staff user can log in and
   operate within their capabilities.
2. **Exact money + atomic rollups** — a small in-house `Money` helper over **BCMath** (exact decimal
   arithmetic; columns stay `decimal:2`, no new dependency, no migration) used by `SaveBudget`,
   `ConvertBudgetToTransaction`, and the form total; `MarkTransactionPaid` LTV and the appointment
   visit-counters become **atomic** (`increment()` inside a transaction).
3. **`x-ui.combobox`** — the in-house searchable-select the program design listed; replace the
   patient/doctor/procedure native `<select>`s on pipeline/calendar/financeiro/booking, and gate the
   full-table loads behind the open form (no loading all patients every render).
4. **Plumbing + domain-event log** — glob the Pest `->in()` tenant list; adopt a migration-ordering
   convention (kill the same-timestamp FK collision we hit 3×); make cross-context listener registration
   consistent + greppable; add a `LogDomainEvent` listener / `metrics` seam capturing the funnel events
   (`PipelineStageChanged`, `BudgetApproved`, `AppointmentNoShow`, transaction paid…).
5. **Recall + revenue dashboard** — render the dashboard (currently a placeholder): the **recall list**
   (`Patient::scopeNeedingRecall`), **recovered revenue** (Σ active-patient LTV), **pipeline value**, and
   **no-show** KPIs — the differentiator made visible. (A thin pull-forward of PRD-9; full analytics stay there.)

*Order:* 1 → 2 (foundation/risk first), then 3/4/5 are independent.

## Testing

Per-slice Pest feature + unit tests as usual. Notable: capability map per role; staff blocked from user
management; admin-created staff can log in; last-admin protection; money math that *would* float-drift
computes exactly; concurrent LTV stays correct; combobox filters server-side; dashboard KPIs/recall list
render the right patients. Browser pass for team management, the combobox, and the dashboard.
